# 成品号订单关联与交付口径

状态：待确认。确认后再改代码。
日期：2026-10-09

## 现象

代理店铺卖出 GPT 成品号后：

- 代理账本、收益、Telegram 通知都有这两笔（例如 `KS202610090335E85KPWE4Q8`、`KS202610090336JPJ3LY4Y8N`）。
- 管理端「订单」里看不到。
- 代理概览「未兑换积压」变成 2，文案是「发出去还没人兑」。账本上「未兑换」也是 2。
- 成品号库存里，未售和已作废的订单列是「—」。已售的那两行其实已经写了上面的订单号和代理名。

## 原因

这是两套单，不是没写上外键。

| 页面 | 读的表 | 成品号店铺单 |
| --- | --- | --- |
| 代理账本、即时发卡 | `store_orders` | 有 |
| 管理端「订单」 | `orders`（兑换 / 开通单） | 没有。成品号付完就交付，不会再建兑换单 |
| 成品号库存 | `finished_accounts.store_order_id` 左连 `store_orders` | 已售有订单号；没卖出的行没有订单，所以是「—」 |

发货时 `fulfillLocalAccountOrder` 会把成品号整行再插进 `issued_cdks`，状态写成 `unused`，`cardplatform_account_id = 0`。未兑换积压统计的是所有 `issued_cdks.status = unused`，所以成品号被当成还没人兑换的卡密。管理端卡密查询已经排除了 `cardplatform_account_id = 0`，所以卡密页看不到它们，只有积压数字被抬高。

成品号买完就把邮箱、密码、Session 交给买家，没有兑换这一步。

## 改法

### 1. 管理端「订单」以商城单为主

现在这一页每一行是兑换单 `RC…`。商城卡密卖出后，要等有人拿去兑换才会出现；成品号不会兑换，所以永远不出现。

改成：一笔商城下单只占一行，订单号用 `KS…`。

| | 卡密套餐 | 成品号 |
| --- | --- | --- |
| 类型 | 卡密 | 成品号 |
| 状态列 | 履约：发卡中、已发卡、部分已发卡、已付未发 | 交付：交付中、已交付、部分交付、待交付 |
| 这一列里的内容 | 打码卡密，张数 | 交付的邮箱，不伪装成卡密 |
| 支付 | 已支付 / 未支付 | 同左 |

没有商城单的兑换（现在的「无商城单」）仍单独占一行，类型是兑换，状态仍是开通成功或失败，操作仍是重拉、明细。

已经挂在某笔 `KS…` 上的兑换单不再在列表里再占一行。点开那笔商城单，详情里有「兑换记录」。这样一次购买不会变成两行。

### 1.1 点「明细」看到的订单详情

商城单的明细至少包括：代理、买家邮箱、套餐、金额、支付渠道、支付状态、时间。

交付内容跟类型走：

- 卡密：发出的卡密。默认打码，点开再看明文，每次写审计。若已经有人拿去兑换，下面列出兑换单号和开通结果。履约状态只表示卡发出去了没有，不表示开通成功。
- 成品号：交付的邮箱、GPT 密码、邮箱密码、Session。默认打码，点开再看。没有兑换记录。交付状态只表示账号交出去了没有。

未支付的商城单也在列表里，状态是待支付，没有交付内容。

### 2. 成品号不要进未兑换积压

新发出的成品号不再以 `unused` 卡密计入积压。

仍把交付内容记在 `issued_cdks`，方便订单明细里看到发给了哪个邮箱，但状态写成 `used`，表示交付完成、没有待兑换。积压查询再排除成品号套餐（`finished_gpt`）和 `cardplatform_account_id = 0`，双保险。

代理概览和账本上的「未兑换 / 未兑换积压」只数真正的卡密。成品号已售数量继续走现有的「已售账号」，不混进积压。

### 3. 把已经记错的两笔改过来

把现有成品号、状态仍是 `unused` 的 `issued_cdks` 改成 `used`。改完 For-Vibe-Coding 的未兑换积压应回到 0（如果没有别的真卡密未兑）。成品号库存上的订单号不动。

### 4. 成品号库存的订单列

已售继续显示订单号和代理。未售、已作废没有订单，继续显示「—」。这里不用改关联。

## 不做

- 不把成品号做成可兑换卡密。
- 不把店铺单写进 `orders` 表去伪装成兑换单。
- 不改代理收益算法。这两笔收益已经在账本里，保持不动。
