# 代理通知与发件人自定义

状态：待确认。确认后再改代码。
日期：2026-10-09

## 谁收到什么

全站仍用管理员配的那一个 Telegram 机器人。客户下单、兑换成功各发两份文案，不能共用现在这一段。

| 事件 | 管理员 | 代理 |
| --- | --- | --- |
| 客户已支付 | 收到，全站每一单 | 只收到自己店铺的单 |
| 兑换成功 | 收到，全站每一笔 | 不收 |
| 兑换失败、提卡、运维告警 | 仍只给管理员 | 不收 |

代理没绑定、或关掉了「接收下单通知」，就跳过他，不影响管理员那份。

## 文案

管理员下单，保持现在的内容：代理是谁、购买人、金额、渠道、套餐、挂牌价、优惠、实付、代理成本、代理收益、平台毛利、上游进价。要发票时还有抬头、税号、开票金额、收票邮箱。

代理下单，同一笔订单改成：

```
[店铺名] 有人下单  KS…
购买人：buyer@example.com
订单金额：¥5.00
支付渠道：微信
套餐：GPT 成品号
你的收益：¥1.96（已扣手续费 ¥0.04）
```

买家要发票时只加一句「这单买家要发票」，不给税号、抬头和开票金额。没有平台毛利，没有上游进价，没有「代理：某某」这一行。

管理员兑换成功，保持现在的内容：兑换单号、代理、开通账号、套餐、售价、代理收益、平台毛利。

## 绑定

代理在自己后台的「通知」里点绑定。系统给一个 10 分钟有效的口令，让他在 Telegram 里给这个机器人发送 `/bind 口令`。机器人拿到的 `chat.id` 记到这个代理名下，一个代理只保留一个会话。

代理不手填 Chat ID。可以解除绑定，也可以只关通知、绑定还留着。管理员在「通知」里能看到谁已绑定，不能改别人的会话。

Bot Token 和平台自己的 Chat ID 仍只在管理员的站点通知里。

## 邮件

SMTP 主机、端口、账号、密码、SSL、STARTTLS、真正的发信地址，只由管理员设置。发信地址必须是这套 SMTP 里已验证的邮箱，例如 `noreply@你的域名`。代理改不了这些。

代理只能设置：

| 项 | 作用 |
| --- | --- |
| 给买家发交付邮件 | 关掉后，他的店付完不发邮件 |
| 发件人名称 | 买家看到的名字，例如 For-Vibe-Coding |
| 回复邮箱 | 买家点回复时进这个邮箱 |

实际发出去的信是：

`From: For-Vibe-Coding <noreply@你的域名>`

`Reply-To: 代理填的回复邮箱`

不能把发件邮箱改成代理自己的 Gmail 或其他域名，否则邮件服务会拒收。

邮件正文只给买家：店铺名、订单号、卡密或成品号内容。没有成本、收益、平台毛利。卡密发齐或成品号交付完成后发送。发送失败不挡住发卡。
