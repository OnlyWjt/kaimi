## 0. 要解决的问题

| # | 现在的问题 | 后果 | 本文章节 |
|---|---|---|---|
| 1 | 代理只看得到一个「可用金额」，看不到自己欠了哪些卡 | 转账前要找你要清单，两边容易对不上 | §2 |
| 2 | 「标记已结算」只改状态，不记收款方式和流水号，结完就看不到了，也撤不回 | 点错无法补救，事后查不到哪天收了多少 | §3 |
| 3 | 代理误提的卡没法作废 | 只能调高上限或假装已结算，账是歪的 | §4 |
| 4 | 超时的单点「确认没出卡」就放额度，不问卡台 | 卡台其实出了卡时，这批卡不在账上，代理还能继续提 | §5 |
| 5 | 「额度」读起来像每月配额 | 代理以为下个月自动恢复 | §6 |
| 6 | 专属链接做了一半：生成了 token，但提卡根本不校验 | 多一个没用的东西 | §7 |
| 7 | 后台不能暂停某个代理提卡，单次、每日上限也改不了 | 发现异常时只能把上限调成 1 分钱 | §8 |

## 1. 总体规则（确认后不再变）

- **上限是循环的**：代理可用金额 = 上限 − 未结金额 − 正在出卡的金额。你登记一次结算，结掉多少就恢复多少。不按月重置。
- **一张卡只有三种账面状态**：未结算、已结算、已作废。只有「未结算」计入欠款。
- **所有改账动作都留痕**：结算、撤销结算、作废、确认没出卡、改上限、暂停/恢复，全部写审计日志，操作人和时间可查。
- **两边看到的是同一份账**：代理页和后台页的张数、金额、对账文本出自同一个函数。

## 2. 代理端：我的提卡账本

### 2.1 页面

代理后台「自助提卡」页，现有的提卡表单下方加三个子页：

```text
┌ 未结 ¥2,800.00 / 上限 ¥3,000.00 ─────────────── 还能提 ¥200.00 ┐
│ ████████████████████████████░░  93%                              │
│ 结算后恢复。转账后请联系平台登记。                                │
└──────────────────────────────────────────────────────────────────┘

[ 未结算 (23) ]  [ 提卡记录 ]  [ 已结算账单 ]

未结算 23 张，合计 ¥2,800.00                     [复制对账文本]
Plus · 菲区 × 20 = ¥2,500.00 · Plus · 美区 × 2 = ¥300.00 …

时间          提卡单        套餐           卡密             使用     金额
09-30 15:30  DR…GH2K     Plus · 美区    ZC-E5C9…D5C      未使用   150.00
09-30 15:30  DR…GH2K     Plus · 美区    ZC-3MNV…7ZRA     已兑换   150.00
09-29 11:02  DR…PP4M     Plus · 菲区    ZC-…             未使用   125.00
```

- **未结算**：一次列出全部未结算的卡，卡密脱敏。上方是按「套餐 · 地区 × 单价」的汇总，和对账文本一致。
- **复制对账文本**：复制出来的内容和你后台复制的完全一样（复用现有 `buildDrawStatementText`），代理可以直接连同转账截图发给你。
- **提卡记录**：按提卡单列出，每行「查看卡密」展开这一单的完整卡密，可再次复制。解决「弹窗关了卡密就找不回来」。
- **已结算账单**：你登记过的每一笔结算：日期、张数、金额、收款方式、状态（已结算 / 已撤销）。点开看这张账单包含哪些卡（脱敏）。

### 2.2 代理端不显示的内容

上游进价、平台毛利、你写的内部备注、别的代理的任何数据。

### 2.3 接口

| 方法 | 路径 | 返回 |
|---|---|---|
| GET | `/api/agent/draw` | 现有字段 + `summary`（未结张数、金额、分组汇总）+ `statementText` |
| GET | `/api/agent/draw/items?status=unsettled` | 未结算行（脱敏） |
| GET | `/api/agent/draw/orders` | 提卡单列表，分页 |
| GET | `/api/agent/draw/orders/[drawNo]` | 单笔完整卡密，只返回自己的，写审计 |
| GET | `/api/agent/draw/bills` | 自己的结算账单列表 |
| GET | `/api/agent/draw/bills/[billNo]` | 账单明细（脱敏） |

## 3. 管理端：登记结算、账单、撤销

### 3.1 登记结算

把现在一点就生效的「标记已结算」改成弹窗：

```text
┌ 登记结算 · 阿明的小店 ─────────────────────┐
│ 共 23 张，金额 ¥2,800.00                     │
│   Plus · 菲区 × 20 = ¥2,500.00              │
│   Plus · 美区 × 2  = ¥300.00                │
│ 时间范围 09-23 10:12 ～ 09-30 15:30          │
│                                             │
│ 收款方式 * [ 支付宝 ▾ ]   支付宝 / 微信 / USDT / 银行 / 其他 │
│ 流水号     [ 2026093022001…          ]      │
│ 备注       [                          ]      │
│                                             │
│ 确认已收到 ¥2,800.00？    [取消] [确认已结算] │
└─────────────────────────────────────────────┘
```

- 收款方式必选，流水号和备注选填。
- 默认勾选全部未结算行。取消勾选部分行就是**部分结算**，弹窗里的金额跟着变。
- 提交时带上勾选的卡 ID 和前端算好的金额。后端重新核对：有卡状态变了、金额对不上，一律拒绝并提示刷新（现有逻辑保留）。
- 成功后生成账单，账单号 `DB…`。

### 3.2 已结算账单子页

提卡账本加第三个子页「已结算」：

```text
筛选：代理 [全部 ▾]                                         [导出 CSV]
账单号      代理        结算时间      张数  金额        方式    流水号     状态     操作
DB…A1B2    阿明的小店  09-30 21:00    23   ¥2,800.00  支付宝  2026…     已结算   [明细][撤销]
DB…C3D4    小鱼        09-27 10:00     5   ¥625.00    USDT   0x8f…     已结算   [明细]       ← 超过 7 天，不能撤销
DB…E5F6    阿明的小店  09-21 20:30     8   ¥1,000.00  微信    …         已撤销   [明细]       ← 灰色
```

### 3.3 撤销结算

- 只能撤销 **7 天内**、状态为「已结算」的账单。
- 必须填写原因。
- 撤销后：账单变成「已撤销」并保留在列表里；账单里的卡全部回到「未结算」；代理的未结金额和可用金额立即按回退后的数字计算。
- 撤销不需要调卡台。

### 3.4 CSV 导出

管理端账本、已结算账单都能导出，UTF-8 带 BOM，Excel 直接打开。列：时间、提卡单、代理、套餐、付款地区、卡密（脱敏）、使用状态、单价、状态、账单号。代理端导出不含上游进价。

## 4. 作废误提的卡

### 4.1 条件

同时满足才能作废：

1. 这张卡在账上是「未结算」；
2. 卡还没被兑换（本地状态是未使用）。

已兑换、已结算的卡不能作废，已结算的要先撤销账单。

### 4.2 流程

管理端账本每行「未使用」的卡多一个「作废」按钮：

```text
┌ 作废这张卡？ ───────────────────────────┐
│ ZC-E5C9…D5C · Plus · 美区 · ¥150.00       │
│ 作废后不再计入阿明的小店的欠款。            │
│                                          │
│ 处理方式                                  │
│ (•) 同时在卡台删卡退款（推荐）              │
│ ( ) 只在本系统作废（卡台已手动处理过）       │
│ 原因 * [ 代理误提，未发出            ]      │
│                          [取消] [作废]    │
└──────────────────────────────────────────┘
```

- **卡台删卡退款**：按现有退款路由的做法，先调卡台删卡退款；卡台返回 404 视为已删；返回 405 改为禁用。其他错误一律**不改本地任何数据**，提示失败原因。
- 卡台处理成功后，在一个事务里：账本行改为「已作废」、记录原因和操作人；卡密状态改为已禁用，兑换页就查不到可用卡了。
- 代理的未结金额立刻减去这张卡。
- 对账文本末尾写「作废 N 张未计入」。

### 4.3 代理能不能自己作废

默认**不能**，由你来作废。理由：作废会从卡台退钱，代理自己操作等于可以反复提、反复退。代理需要作废时在群里告诉你。

## 5. 超时单的找回

### 5.1 现在的问题

卡台超时（结果未知）时，这一单继续占着额度，这是对的，因为卡台可能已经出了卡。但目前后台只有「确认没出卡」一个按钮，点了就释放额度，不向卡台核对。

### 5.2 改成两步

后台代理详情里，卡住的单显示成：

```text
⚠ DR…9K2M · Plus · 美区 × 3 · ¥450.00 · 卡台响应超时，还占着额度
   [ 向卡台取回 ]   [ 确认没出卡 ]（灰色，先取回一次才能点）
```

1. **向卡台取回**：用这一单**原来的幂等键**再请求一次卡台。卡台对同一个键只会返回同一批结果，不会多出卡。
   - 拿到卡：入库、记账，这一单变成「已出卡」或「部分出卡」，代理那边的提卡记录里能看到卡密。
   - 卡台明确回复没有出卡（空结果或业务错误）：这一单变成「失败」，额度释放。
   - 仍然超时：保持原样，可以稍后再点。
2. **确认没出卡**：至少取回过一次、并且仍然拿不到明确结果时才可以点。点之前要求输入这一单的提卡单号后四位，防止误点。这一步只在你已经去卡台后台人工核对过时使用。

### 5.3 代理那边

- 提卡时如果超时，页面提示「卡台还没返回结果，没有重复扣费。再点一次会取回同一笔」。代理再点同一笔就是自动取回，不会生成新的一单。
- 这一单处于找回中时，代理页的提卡记录显示「找回中」，额度里算作「正在出卡」。

### 5.4 自动找回（可选）

后台定时任务每 5 分钟对超时超过 5 分钟的单自动取回一次，最多 6 次。仍然没有结果就发一条 Telegram：「提卡结果未知，需要人工核对」。默认**开启**。

## 7. 专属链接

第一版设计是「登录 + 链接」才能提卡。实际代码里代理登录就能提，链接从来没有被校验。

**建议去掉专属链接**，理由：

- 代理登录本身已经是身份校验；
- 挡住账号被盗后一次提光的，是上限、单次最多张数、每次提卡发 Telegram、以及后台一键暂停（§8），不是链接；
- 链接要复制、要收藏、要重置，全是额外操作。

处理方式：界面上不出现链接；数据库列保留不删；设计文档 D9 改为「只要登录」。

## 8. 后台可调参数与暂停

代理详情里，把「调整上限」扩成一个「提卡设置」区块：

```text
提卡设置
  上限       ¥ [ 3000.00 ]
  单次最多   [ 10 ] 张        1–200
  每日最多   [ 0  ] 张        0 = 不限
  每次提卡发 Telegram  [✓]
                                     [保存设置]
  [ 暂停提卡 ]   ← 已暂停时显示 [ 恢复提卡 ]
```

- **暂停**：代理立即不能提卡；已有的未结算照常显示、照常可以结算和作废。代理页显示「平台已暂停你的提卡，如有疑问请联系平台」。
- **恢复**：回到已开通，上限等参数不变。
- 改上限时，如果新上限低于当前未结金额，保存成功，但提示「他要先结算一部分才能再提」（第一版已有）。

## 9. 顺手修的两个问题

1. **取回时出卡张数算错**：现在按「这次新写入的张数」判断一单出了几张。取回时卡台重放上一次的结果，这些卡已经在库里，新写入为 0，这一单会被错误地标成「失败」并释放额度。改为按「这一单在账本里的总张数」判断。
2. **「结果未知」的单不会被再次处理**：现在代理再点同一笔，只会重试「出卡中」的单，「结果未知」的单直接原样返回。改为两种状态都走 §5 的取回。
