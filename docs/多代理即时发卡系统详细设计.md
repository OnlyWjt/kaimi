## 2. 已确认的产品规则

以下规则已经确认，不再作为实施待定项：

1. Kaimi 由平台统一部署，升级为多代理系统，不再给每个代理单独部署一套。
2. 系统角色包括超级管理员和代理账号。
3. 超级管理员创建、禁用代理账号，并设置代理可售套餐和代理成本价。
4. 每个代理拥有一个公开店铺链接：`/s/{slug}`。
5. 代理只允许修改链接中的 `slug`，不能自定义完整域名或路径结构。
6. 一个代理只有一个店铺链接，打开后展示该代理可售的全部商品，例如：
   - Plus
   - Pro 5x
   - Pro 20x
7. 代理可为每个商品设置自己的零售价，但零售价不能低于超级管理员设置的代理成本价。
8. 客户在 Kaimi 内完成下单和易支付付款，资金进入平台统一配置的易支付商户。
9. 客户付款成功后，Kaimi 直接调用卡台生成一张新的卡密，不要求代理预先囤货。
10. 卡台生成的完整卡密必须立即保存到 Kaimi，并返回给客户。
11. 已售卡密归属对应代理，代理可以在后台查看自己的完整卡密和兑换状态。
12. 代理收益计算时需要扣除代理成本价和实际支付渠道的易支付手续费。
13. 支付宝与微信支付费率分开配置。
14. 代理可以按今天、近 7 天、本月和自定义时间范围查看收益汇总及明细。
15. 卡台接入逻辑参考 `danew_card_cdk`，在 Kaimi 的 TypeScript 技术栈中做等价迁移，不复制一套不兼容的 Go 运行时。

## 3. 产品定位

### 3.1 新定位

Kaimi 是平台统一运营的多代理即时发卡和兑换系统：

- 平台负责易支付商户、卡台资金、卡台凭证、商品底价和代理结算。
- 代理负责推广自己的店铺链接和设置零售价。
- 客户从代理店铺付款，支付成功后由平台即时生成新卡密。
- 卡密可以在 Kaimi 的兑换页提交凭据并完成开通。
- 平台按订单记录代理收益，并定期向代理返佣。

### 3.2 不再采用的模式

新业务主路径不再包含：

- 代理先向平台购卡
- 代理提前持有未售库存
- 代理自己配置易支付
- 代理自己收客户资金
- 每个代理单独部署一套 Kaimi
- 客户先跳到外部发卡网买码，再返回 Kaimi

旧库存可以保留一段迁移期，但不能继续作为新订单的默认发货来源。

- 针对单个代理覆盖成本价
- 设置代理可售套餐
- 查看代理零售价
- 配置支付宝和微信手续费
- 配置易支付商户
- 配置卡台账户、凭证和发码参数
- 查看全站订单、支付、发码和异常
- 查看全站卡密及其代理归属

- 创建结算单并标记已返佣
- 对退款订单执行收益冲正
- 查看操作审计日志

### 4.2 代理账号

代理只能访问自己的数据：

- 登录代理后台
- 修改自己的登录密码
- 修改自己的店铺 slug
- 查看自己的完整店铺链接
- 查看超级管理员允许销售的套餐

- 设置每个套餐的零售价

## 5. 核心业务流程

### 5.1 代理开通流程

1. 超级管理员创建代理账号。
2. 系统生成默认 slug，例如 `agent-1001`。
3. 超级管理员为代理勾选可售套餐。
4. 系统读取全局代理成本价；若存在代理覆盖价，则使用覆盖价。
5. 代理登录后修改自己的 slug。
6. 代理为每个套餐设置零售价。
7. 代理复制店铺链接进行推广。

### 5.2 客户购卡流程

```text
访问 /s/{slug}
  → 识别代理
  → 展示该代理可售商品及零售价
  → 客户选择商品和支付渠道
  → 创建本地待支付订单
  → 固化代理、套餐、零售价、成本价和手续费规则快照
  → 跳转易支付
  → 易支付异步通知
  → 验签、校验商户订单号和金额
  → 将订单标记为已支付
  → 使用订单级幂等键调用卡台生成一张新卡密
  → 保存完整卡密
  → 将订单标记为已发货
  → 生成代理收益明细
  → 客户订单页展示卡密
```

### 5.3 支付成功但卡台发码失败

支付成功不等于发卡成功。发生超时、卡台不可用、余额不足或完整码缺失时：

1. 订单支付状态保持 `paid`。
2. 履约状态进入 `paid_undelivered`。
3. 客户页显示“支付成功，正在发卡，请稍后刷新”。
4. 系统记录本次发码尝试和错误码。
5. 自动任务使用原订单的同一个幂等键重试。
6. 超级管理员可手工触发重试。
7. 未确认首次调用失败前，禁止换新幂等键再次生成。
8. 卡密成功落库后才能生成代理收益。

### 5.4 兑换流程

购卡和兑换是两个独立阶段：

1. 客户付款后得到卡密。
2. 客户进入 `/recharge`。
3. Kaimi 校验本地卡密状态和套餐。
4. 客户提交 Session 或邮箱凭据。
5. Kaimi 调用卡台/上游兑换接口。
6. Webhook 或轮询更新兑换状态。
7. 客户和所属代理均可以查看卡密的兑换状态。

兑换失败不能自动再生成新卡密。换码应作为独立售后功能，在后续阶段实现。

## 6. 代理店铺和 slug 设计

### 6.1 店铺地址

公开地址固定为：

```text
https://平台域名/s/{slug}
```

示例：

```text
https://kaimi.example.com/s/zhangsan
```

一个链接展示该代理全部可售商品，不为每个商品创建单独链接。

### 6.2 slug 规则

- 长度：3–32 个字符
- 仅允许小写英文字母、数字和短横线
- 必须以字母或数字开头、结尾
- 全站唯一，不区分大小写
- 保存前统一转为小写
- 禁止连续短横线
- 不允许使用保留词

保留词至少包括：

```text
admin
api
login
logout
agent
partner
recharge
lookup
cdk
shop
order
orders
assets
_next
favicon
www
support
```

### 6.3 slug 修改

- 代理可以修改自己的 slug。
- 修改时必须再次校验格式和唯一性。
- 原 slug 写入历史表。
- 原链接永久跳转到当前链接，防止已推广链接立即失效。
- 历史 slug 不得被其他代理重新占用，避免订单归因和钓鱼风险。
- 代理被禁用后，当前链接和历史链接均显示“店铺暂时关闭”。

### 6.4 店铺商品展示

商品是否展示必须同时满足：

1. 平台套餐已启用。
2. 该代理被允许销售该套餐。
3. 该代理已设置有效零售价。
4. 零售价不低于当前代理成本价。
5. 卡台套餐处于可售状态；卡台临时不可达时可显示“暂不可购买”，不得盲目收款。

## 7. 商品和价格模型

### 7.1 套餐

套餐键使用卡台的稳定 plan key，不在前端写死套餐清单。首期目标套餐：

- `plus`
- `pro_5x`
- `pro_20x`

后续新增套餐时，通过卡台套餐同步和超级管理员启用即可出现，不要求重新发布前端。

### 7.2 三种价格

系统必须区分：

1. **卡台实际成本**：平台向卡台支付的真实成本，只对超级管理员可见。
2. **代理成本价**：平台给代理的结算底价，例如 ¥1030。
3. **代理零售价**：代理给客户的售价，例如 ¥1080。

代理收益只使用代理成本价，不直接使用卡台实际成本：

```text
代理收益 = 客户实付金额 - 代理成本价 - 易支付手续费
```

平台毛利另行计算：

```text
平台毛利 = 代理成本价 - 卡台实际成本
```

若平台决定自己承担部分支付手续费，可以在后续增加分摊规则；首期全部从代理差价中扣除。

### 7.3 成本价生效顺序

```text
代理套餐覆盖价
  → 全局套餐代理成本价
  → 未配置：该代理不可销售该套餐
```

### 7.4 价格快照

创建订单时固化以下信息：

- 商品名称和 plan key
- 代理 ID
- 客户实付金额
- 代理成本价
- 预计支付渠道
- 支付渠道费率
- 固定手续费
- 预计手续费
- 预计代理收益

支付成功后以实际支付渠道重新确认手续费并固化最终值。历史订单不随以后调价变化。

## 8. 易支付和手续费

### 8.1 平台统一配置

超级管理员配置一套易支付商户：

- 网关地址
- 商户 PID
- 商户密钥
- 支付宝是否启用
- 微信支付是否启用
- 支付宝费率
- 微信支付费率
- 支付宝单笔固定费用
- 微信支付单笔固定费用
- 回调公网地址

费率建议使用百万分比整数保存，避免浮点误差。例如：

```text
0.6% = 6000 ppm
```

金额始终使用人民币分保存。

### 8.2 手续费公式

```text
百分比手续费 = round(实付金额分 × 费率 ppm ÷ 1,000,000)
最终手续费 = 百分比手续费 + 渠道固定费用分
代理收益 = 实付金额分 - 代理成本价分 - 最终手续费分
```

示例：

```text
客户实付：¥1080.00
代理成本：¥1030.00
支付宝费率：0.6%
固定费用：¥0.00
手续费：¥6.48
代理收益：¥43.52
```

### 8.3 回调约束

易支付通知必须：

- 支持 GET 或 POST 参数
- 验证签名
- 验证 `trade_status`
- 验证本站订单存在
- 验证通知金额与订单金额完全一致
- 按支付平台交易号幂等
- 重复通知只返回成功，不重复发码
- 非本站订单前缀不得进入发卡流程
- 日志不得记录易支付密钥

### 8.4 手续费差异

部分易支付网关的回调不会返回真实手续费。支付成功时先按后台配置的渠道费率生成“预计手续费”，随后由自动对账任务查询网关交易详情，取得“实际手续费”并修正收益。

1. 保存“规则计算手续费”和“网关实际手续费”。
2. 对账完成前，代理收益状态为 `estimated`，页面明确标记“手续费待对账”。
3. 对账成功后，收益改为 `confirmed`，最终收益优先使用网关实际手续费。
4. 若网关明确不提供手续费字段，则状态记为 `unsupported`，最终值回落到规则计算手续费。
5. 查询失败时按退避策略重试，不能把预计手续费误标为实际手续费。
6. 差异超过后台配置阈值时产生财务告警。
7. 已结算订单出现手续费修正时，生成正数或负数收益调整项，不直接篡改已结算记录。

### 8.5 网关实际手续费自动对账

易支付适配器增加交易查询能力：

```text
queryOrder(outTradeNo | tradeNo)
  → 支付状态
  → 实付金额
  → 实际支付渠道
  → 网关手续费（网关支持时）
  → 网关原始交易数据摘要
```

对账任务处理范围：

- 已支付且尚未完成手续费对账的订单
- 网关查询失败、尚未超过最大重试次数的订单
- 超级管理员手工要求重新对账的订单

对账校验：

- 网关订单号与本站订单一致
- 网关商户号与当前配置一致
- 网关实付金额与本站订单一致
- 网关支付状态为成功
- 手续费必须是非负金额，且不能大于实付金额
- 原始响应保存前移除密钥和签名

默认重试节奏：1 分钟、5 分钟、30 分钟、2 小时、12 小时、24 小时。超过 24 小时仍无法确认时进入 `manual_review`。

超级管理员后台需要展示预计手续费、实际手续费、差额、对账状态和最后错误，并提供“重新对账”操作。

### 9.3 卡台账户配置

至少保存：

- 名称
- Base URL
- 协议类型
- API Key 或 App ID/App Secret（加密）
- Webhook Secret（加密）
- 是否启用
- 是否默认
- 最近健康检查时间
- 最近错误
- 最近同步套餐时间

浏览器永远不能读取完整凭证。

### 9.4 发码要求

- 首期客户订单数量固定为 1 张，降低支付后部分发货风险。
- 发码幂等键固定由本地订单生成，例如 `kaimi-order-{orderNo}`。
- 同一订单重试必须复用同一个幂等键。
- 必须设置独立的卡台请求超时。
- HTTP 成功但业务 code 失败时按业务失败处理。
- 卡台返回完整码后，必须先写入数据库，再把订单标记为已发货。
- 卡台未返回完整码时，不得标记已发货。
- 完整码只在服务端持久化，不写入日志或错误堆栈。
- 卡台返回的上游 ID、码前缀、套餐、费用和原始状态要一并保存，便于对账。

### 9.5 卡台套餐同步

- 后台手工同步
- 定时同步
- 保存原始响应和同步时间
- 只展示卡台可售且平台启用的套餐
- 卡台新增套餐时后台可见，但默认不自动开放给代理
- 卡台不可用时保留最近缓存，但店铺购买按钮应按健康策略禁用

### 9.6 发码重试

可安全自动重试：

- 网络连接失败
- 明确的超时
- HTTP 429
- HTTP 502/503
- 卡台明确返回“处理中”

不可盲目重试：

- 鉴权失败
- IP 白名单失败
- 套餐不存在
- 余额不足
- 明确的参数错误
- 首次请求结果不确定且上游不支持同幂等键查询/重放

对于“结果不确定”，订单进入人工核对状态，禁止使用新幂等键再次发码。

## 10. 订单状态机

### 10.1 支付状态 `pay_status`

- `unpaid`：未支付
- `paid`：支付成功
- `expired`：支付超时
- `cancelled`：已取消
- `refunded`：已退款

### 10.2 履约状态 `fulfill_status`

- `pending`：等待支付
- `issuing`：正在向卡台发码
- `delivered`：完整码已保存并交付
- `paid_undelivered`：已支付但发码失败
- `unknown`：上游结果不确定，必须人工核对
- `cancelled`：订单已取消
- `refunded`：已退款

### 10.3 合法流转

```text
unpaid/pending
  → paid/issuing
  → paid/delivered
```

异常流转：

```text
paid/issuing
  → paid/paid_undelivered
  → paid/issuing
  → paid/delivered
```

结果不确定：

```text
paid/issuing
  → paid/unknown
  → 人工对账
  → paid/delivered 或 refunded/refunded
```

收益只允许在 `paid + delivered` 后创建。

## 11. 卡密归属和可见性

### 11.1 归属

每张销售卡密必须绑定：

- 本地订单
- 代理
- 套餐
- 卡台账户
- 卡台上游 ID
- 完整码
- 码前缀
- 发码时间
- 当前兑换状态

### 11.2 代理“我的卡密”

代理可以看到自己店铺已售出的卡密：

- 完整卡密
- 商品/套餐
- 本地订单号
- 售出时间
- 客户实付
- 当前卡密状态
- 兑换时间

代理看不到：

- 其他代理卡密
- 卡台 API 凭证
- 平台真实卡台成本
- 客户提交的 Session、邮箱密码等敏感凭据

### 11.3 客户订单页

客户只能在满足以下条件时查看完整卡密：

- 订单已支付
- 履约状态为 `delivered`
- 查询令牌或订单查询凭证正确

只凭连续递增订单号不得查看卡密。订单号必须不可预测，并配合独立查询令牌或客户邮箱校验。

## 12. 收益、退款和结算

### 12.1 收益确认

订单完成发卡时创建一条不可变收益快照：

- 订单号
- 代理
- 套餐
- 客户实付
- 代理成本价
- 支付渠道
- 渠道费率
- 固定手续费
- 最终手续费
- 代理收益
- 收益确认时间

同一订单只允许一条有效收益记录。

### 12.2 收益状态

- `pending`：已确认收益，尚未结算
- `settling`：已加入结算单
- `settled`：已返佣
- `reversed`：退款或异常冲正

### 12.3 退款

退款必须同步处理卡密和收益：

1. 若未发码：退款后不创建收益。
2. 若已发码但卡密可安全作废：先作废/退款，再冲正收益。
3. 若卡密已经兑换：默认禁止自动退款，转人工处理。
4. 待结算收益直接冲正。
5. 已结算收益生成负数调整项，从代理下一期收益扣除。
6. 所有退款和冲正必须进入审计日志。

### 12.4 结算

首期采用人工返佣：

1. 超级管理员选择代理和结算截止时间。
2. 系统锁定该范围内所有 `pending` 收益。
3. 创建结算单并计算总额。
4. 超级管理员线下转账。
5. 填写转账渠道、流水号和备注。
6. 标记结算单已支付。
7. 对应收益改为 `settled`。

### 12.5 时间查询

代理后台提供：

- 今天
- 昨天
- 近 7 天
- 本月
- 上月
- 自定义开始和结束时间

收益按 `earning_confirmed_at` 统计；结算记录按 `settled_at` 统计。系统统一保存 UTC，页面按站点配置时区展示，默认 `Asia/Shanghai`。

汇总指标：

- 成交订单数
- 客户实付总额
- 代理成本总额
- 易支付手续费总额
- 代理收益总额
- 待结算收益
- 已结算收益
- 已冲正收益

明细字段：

- 收益确认时间
- 订单号
- 套餐
- 支付渠道
- 客户实付
- 代理成本价
- 手续费
- 代理收益
- 结算状态
- 卡密状态

### 12.6 收益账单导出 Excel

超级管理员和代理均可导出 `.xlsx`：

- 超级管理员可选择全部代理或指定代理。
- 代理只能导出自己的数据。
- 导出筛选条件与页面一致：时间范围、套餐、支付渠道、收益状态、结算状态。
- 文件名包含角色范围和时间，例如 `kaimi-earnings-agent-1001-20260901-20260930.xlsx`。
- 默认最多导出 50,000 条；超出时拒绝同步导出并提示缩小范围，后续再扩展异步导出。

工作簿包含：

1. **收益汇总**
   - 时间范围
   - 代理
   - 成交订单数
   - 客户实付总额
   - 代理成本总额
   - 预计手续费
   - 实际手续费
   - 手续费差额
   - 最终收益
   - 待结算、已结算、已冲正金额
2. **收益明细**
   - 收益确认时间
   - 订单号
   - 代理
   - 套餐
   - 支付渠道
   - 客户实付
   - 代理成本价
   - 预计手续费
   - 实际手续费
   - 手续费对账状态
   - 最终手续费
   - 最终收益
   - 收益状态
   - 结算单号
   - 卡密状态
3. **结算记录**
   - 结算单号
   - 结算周期
   - 结算金额
   - 打款渠道
   - 打款流水号
   - 结算时间

导出要求：

- 使用服务端生成 Excel，首期采用 `exceljs`。
- 金额单元格写数值并设置人民币格式，不能写成带 `¥` 的字符串。
- 时间按站点时区导出。
- 防止公式注入：任何以 `=、+、-、@` 开头的外部文本必须转义。
- 不导出完整卡密、客户凭据、支付密钥或卡台凭证。
- 导出操作写入审计日志。

## 16. 安全要求

### 16.1 凭证

- 卡台密钥、Webhook Secret、易支付密钥加密落库。
- 加密主密钥只能来自环境变量。
- API 响应只返回是否已配置和脱敏提示。
- 任何服务端日志不得输出完整密钥。

### 16.2 登录和权限

- 密码使用 bcrypt/argon2 哈希。
- 会话 Cookie 使用 `HttpOnly + Secure + SameSite=Lax`。
- 超级管理员和代理接口使用统一 RBAC 中间件。
- 代理数据查询必须强制加 `agent_id` 条件。
- 登录、改价、查看卡密和结算接口增加速率限制。

### 16.3 卡密

- 完整卡密加密保存，同时保存不可逆哈希做检索。
- 客户和代理展示完整码时记录审计。
- 卡密不得进入访问日志、错误日志和客户端埋点。
- 订单查询地址必须带不可预测令牌。

### 16.4 Webhook

- 易支付和卡台回调分别验签。
- 先读取原始请求体再验签。
- 校验时间窗（协议支持时）。
- 事件 ID 去重。
- 数据库处理成功后才返回成功。
- 长耗时发码不应阻塞 Webhook 到超时：建议回调只落支付状态和履约任务，随后由同进程任务立即执行；如果首期同步执行，必须保证回调超时策略和可重入。

## 17. 并发、事务和幂等

### 17.1 创建订单

- 服务端读取价格并生成快照。
- 同一客户端重复点击可通过短期请求幂等键防重复下单。
- 首期一个订单只允许买一张卡密。

### 17.2 支付通知

在单个数据库事务中：

1. 锁定或条件更新订单。
2. 校验当前状态。
3. 写支付交易号。
4. 标记已支付。
5. 创建唯一履约任务。
6. 写 Webhook 处理结果。

唯一约束防止重复通知产生多个履约任务。

### 17.3 发卡

- 使用条件更新把 `paid_undelivered` 或首次 `pending` 改为 `issuing`。
- 同一订单同一时间只允许一个履约执行者。
- 发码调用使用固定幂等键。
- 卡密落库、订单交付、收益创建尽量在同一数据库事务完成。
- 如果卡台成功但本地落库失败，必须使用同幂等键恢复，不得重新生成。

## 22. 风险和控制

### 22.1 卡台完整码只短时返回

控制：卡台成功响应后先保存完整码，再更新订单。任何日志都不能替代数据库持久化。

### 22.2 支付成功但卡台不可用

控制：使用 `paid_undelivered`、固定幂等键、自动重试和人工对账，不能直接给客户显示支付失败。

### 22.3 重复发码造成资金损失

控制：订单唯一履约任务、固定幂等键、数据库条件更新和卡台重放协议共同保证。

### 22.4 代理调价导致负收益

控制：保存时校验，创建订单时再次校验。若成本价被超管上调导致现有零售价失效，商品立即暂停销售并提示代理改价。

### 22.5 手续费与实际账单不一致

控制：首期保留费率快照；后续接入网关实际手续费后做差异对账。

### 22.6 完整卡密泄露

控制：加密落库、默认脱敏、按代理隔离、查看审计、查询令牌和日志脱敏。
